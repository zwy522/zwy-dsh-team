# 单一格式计算执行部件的面积–能耗效率研究方案

> 状态：研究方案 v0.2（**本阶段不运行实验、不产出测量数据**）
> 日期：2026-11-04
> 范围：为“原生单一计算执行部件，后续支持多种数据格式”的硬件确定基础计算格式
> 关联材料：OzCore（MICRO 2026）及同目录下的 Ozaki-II / FP8 / FP4 论文

## 摘要

本方案回答一个选型问题：在 **INT8、FP8 (E4M3)、FP4 (E2M1)** 三种低精度格式中，哪一种最适合作为“统一多格式计算执行部件”的基础计算格式（base compute fabric）。

这个问题的难点不是比较单个 MAC 的面积或能耗，而是三种格式的**数值能力不同、达到同一精度所需的低精度 GEMM 次数不同**。OzCore 已经证明：INT8 计算阵列可以通过 Ozaki Scheme II 的整数剩余域分解，以约 3 次 INT8 GEMM 达到 BF16 等价精度；FP8 和 FP4 也有各自的 Ozaki 分解方案，但每提升一次精度所需的 pass/limb 数不同。若只看单 MAC 效率，FP4 必然最小；但若把“达到目标精度所需的 pass 数 + 预处理/后处理开销”算进去，排名可能改变。

因此本方案把评价分成两层：

1. **原始硬件效率**：单位面积、单位能耗的峰值吞吐（TOPS/mm²、TOPS/W），以及二者合成的面积–能耗效率 `AEE`。
2. **等精度有效效率**：先为每种格式找到达到目标精度（BF16 等价 / FP32 等价）所需的最小 pass 数，再用“有效吞吐 = 峰值吞吐 / pass 数”比较包含预处理、后处理在内的整机面积–能耗效率。

面积用可综合 RTL/HLS + 标准单元库测量，能耗用综合后功耗分析估算，精度和 pass 数用位精确软件模型 + 工作负载实验测定。三种格式共用同一阵列规模、同一工艺、同一频率、同一累加器精度和同一辅助逻辑边界，保证比较可解释。

本阶段只交付方案与实验设计，不运行综合、仿真或训练。

## 1. 背景与问题

### 1.1 从 OzCore 得到的出发点

OzCore 的核心结论是：**不需要为每种浮点格式做专用数据通路**，可以用一个 INT8 计算阵列，通过 Ozaki Scheme II 的整数模分解 + CRT 重构，统一支持 FP32/FP16/BF16/FP8/INT8 输入。论文报告：

- 单个 OzCore（128×128 INT8 MAC 阵列 + 前后处理）在 28 nm、300 MHz 下约 6.03 mm²，其中 INT8 阵列占 72.1%，前后处理只增加 27.9% 面积；
- 相比融合多格式基线，在等精度下达到 1.91× TOPS/mm² 和 1.40× TOPS/W；
- 在 LLaMA-3.1 8B/70B 上，split count `s = 3` 即可匹配 BF16 困惑度，`s = 2` 为近似模式，`s = 12` 接近 FP32 精度。

同目录的另外两篇论文把“基座格式”的问题推到了前台：

- **FP8 E4M3**：Ozaki-II 不能直接把 INT8 版本换成 FP8；需要把每个模数的剩余拆成多个 FP8 部分积，用 3 次 FP8 GEMM 实现一个模数的精确乘积（FP32 累加），并用更多模数达到 FP64 精度。
- **FP4 E2M1**：FP4 只有 1 位尾数，不能直接承载剩余；但把 FP4 值乘 2 后都是整数，用 base-13 表示可以把任意整数拆成 FP4 limb，且中间和在 FP32 累加器中保持精确。在 Blackwell 代 GPU 上，FP4 张量核的标称吞吐是 FP8 的 2×，但达到同一精度需要的模数/limb 更多（例如 DGEMM 下 FP8 需要 13 个模数，FP4-OzII 需要 19 个模数）。

三篇论文共同指向一个尚未被系统回答的问题：**在给定精度目标和工艺约束下，哪种低精度格式作为统一执行部件的基座，能获得最高的面积–能耗效率？** 这正是本方案要验证的问题。

### 1.2 本阶段要回答的问题

- Q1：INT8、FP8 E4M3、FP4 E2M1 三种格式的 MAC 阵列，在相同阵列规模、工艺、频率、累加器精度下，面积、功耗、峰值吞吐分别是多少？
- Q2：为达到同一精度目标（BF16 等价、FP32 等价），三种格式各自需要多少次低精度 GEMM（pass/limb 数）？前后处理（缩放、分解、模约简、CRT/重构、格式转换）的面积和能耗是多少？
- Q3：把 pass 数和辅助逻辑计入后，哪种格式的**等精度面积–能耗效率**最高？差距是否随精度目标、工艺节点、阵列规模变化？
- Q4：是否存在“单一格式在所有目标上都最优”？若不存在，Pareto 前沿是什么，应按什么规则选型？

### 1.3 不在本阶段范围内

- 完整加速器（SRAM、NoC、DMA、编译器、内核调度）的设计与实现；
- 硅后测量、流片、版图 Signoff；
- 新的 Ozaki 分解算法或数值方法创新（本阶段复用论文算法，只做硬件比较）；
- 多格式统一执行部件的完整 RTL（本阶段分别实现三种“单格式基座 + 该格式的分解逻辑”，为后续统一化提供依据）；
- 更多格式（FP6、MXFP4、INT4 权重、Posit 等）——作为后续扩展，见 2.5。

### 1.4 关键假设与约束

- **“执行部件”边界**：一个 `128×128` 的 MAC 阵列 + 该格式所需的预处理/后处理逻辑 + 控制逻辑；不含 SRAM/NoC/DRAM。这个边界与 OzCore 论文一致，便于复现和对齐。
- **工艺/频率**：主实验用 28 nm CMOS、300 MHz，与 OzCore 论文一致；另做 7 nm/5 nm 缩放敏感性（只作投影，不作主排名）。
- **累加器**：INT8 → INT32；FP8 E4M3、FP4 E2M1 → FP32。这是三种格式在现有 GPU/加速器上的典型配置，也是 Ozaki 分解保持中间和精确的前提。
- **精度目标**：主目标为 BF16 等价（LLM 推理，对应 OzCore 的 `s=3` 场景）；辅目标为 FP32 等价（统一执行部件面对的高精度 GEMM），并可选做 FP64 等价（对应 FP8/FP4 论文的 DGEMM 场景）。各目标分别排名，不混为一个。
- **pass 数不是常数**：它由格式的数值能力、模数/limb 选择、输入动态范围共同决定；本方案要求用实验测定，而不是假设 FP4 一定是 FP8 的一半、INT8 一定是 3 次。
- OzCore 及同目录论文的原文已读取；本方案引用其公开结论，但不把论文的最优实现当作三种格式的公平实现——三种格式都要在同一流程下重新实现和测量。

## 2. 候选格式

### 2.1 三种候选

| 维度 | INT8 | FP8 E4M3 | FP4 E2M1 |
|---|---|---|---|
| 编码 | 8-bit 补码整数 | 1 符号 + 4 指数 + 3 尾数 | 1 符号 + 2 指数 + 1 尾数 |
| 可表示值 | −128 … 127 | 约 ±448（有限值） | 0, ±0.5, ±1, ±1.5, ±2, ±3, ±4, ±6 |
| 累加器 | INT32 | FP32 | FP32 |
| 典型分解方案 | Ozaki-II + CRT（OzCore） | Ozaki-II 的 FP8 变体（每模数 3 次 FP8 GEMM） | base-13 limb 表示（Ozaki-I/II） |
| 每 limb/模数的有效位 | 约 8 bit | 约 4 bit 尾数 + 指数 | 约 log2(13) ≈ 3.70 bit |
| 硬件特征 | 整数乘法器，无对齐/规格化 | 指数 + 尾数乘法 + 对齐/规格化/舍入 | 极小乘法器，但需要 base-13 编码/解码 |
| 论文中的定位 | OzCore 的基线基座 | 面向 FP8 原生算力的 Ozaki-II 方案 | 面向 FP4 2× 吞吐的 Ozaki 方案 |

### 2.2 为什么是这三种

三种格式代表三条不同的“效率来源”：

1. **INT8**：用**精确整数**换效率。剩余域和 CRT 重构都是整数运算，语义最干净；代价是每个 pass 只有 8 bit 左右的有效位，达到高精度需要多个 pass。
2. **FP8 E4M3**：用**浮点指数**换动态范围。每个 pass 的有效位更少（尾数 4 bit），但硬件与 INT8 同量级；适合“原生 FP8 算力已经存在、INT8 算力被削减”的硬件趋势。
3. **FP4 E2M1**：用**更小的乘法器 + 更高吞吐**换效率。每个 limb 只有约 3.70 bit，达到同一精度需要更多 limb/模数；论文给出的 break-even 约在 FP4:FP8 吞吐比 1.9×；只有超过这个比值，FP4 才可能在等精度下胜出。

这三种恰好覆盖“整数 / 8-bit 浮点 / 4-bit 浮点”三个基座选项，也对应同目录三篇论文的三种技术路线。BF16、FP16、FP32 不作为基座候选：它们是统一执行部件要**支持**的输入/输出格式，而不是基座计算格式；把它们作为基座会退化为“格式原生融合”，OzCore 已经论证其面积效率较低。

### 2.3 被支持格式（I/O 格式）

统一执行部件最终要支持：FP32、TF32、FP16、BF16、FP8 E4M3/E5M2、INT8（可选 INT4 权重）。这些格式是精度目标和 workload 的一部分，不作为基座候选。实验中它们用于：

- 定义精度目标（BF16 等价、FP32 等价）；
- 生成真实激活/权重 trace；
- 作为融合多格式基线的对照（可选）。

### 2.4 与论文的对应关系

| 格式 | 参考方案 | 关键机制 | 需要在本实验中复现/测量的量 |
|---|---|---|---|
| INT8 | OzCore | Ozaki-II + CRT，`s` 个模数，INT32 累加 | 面积、功耗、`s` vs 精度、TOPS/mm²、TOPS/W |
| FP8 E4M3 | Uchino et al. | 每模数 3 次 FP8 GEMM，FP32 累加，模数 p≤513 | 面积、功耗、模数数 vs 精度、有效吞吐 |
| FP4 E2M1 | Hayashi et al. | base-13 limb，FP32 累加，19 模数（DGEMM） | 面积、功耗、limb 数 vs 精度、FP4:FP8 吞吐比敏感性 |

### 2.5 边界候选

以下格式不进主实验，但在讨论和敏感性分析中出现：

- **INT4**：若只做推理，INT4 权重可进一步降低面积；但 INT4 不能直接承载 CRT 剩余，需要更复杂的打包/解包，且精度风险大。
- **MXFP8 / MXFP4**：块缩放格式会改变“格式”与“精度”的关系，作为与 OzCore 路线的对照。
- **FP8 E5M2**：与 E4M3 同族，动态范围更大、精度更低；用于验证 E4M3 结论是否依赖尾数/指数划分。
- **FP6 / FP16**：作为“中间宽度”的边界，用来说明位宽趋势。

## 3. 执行部件与比较基线

### 3.1 统一执行部件的抽象

三种候选共享同一个顶层结构，只替换“计算阵列 + 分解/重构逻辑”：

```
输入（FP32/BF16/FP16/FP8/INT8）
        │
        ▼
[预处理] 缩放、拆分、模数/limb 编码、格式转换
        │
        ▼
[计算阵列] 128×128 MAC（INT8 / FP8 / FP4），INT32 或 FP32 累加
        │
        ▼
[后处理] 模约简、CRT/limb 重构、反缩放、格式转换
        │
        ▼
输出（FP32/BF16/...）
```

关键点：**预处理和后处理必须计入面积/能耗**。OzCore 的 27.9% 面积开销主要来自这里；FP8/FP4 的分解逻辑更复杂，若只比 MAC 阵列会得出错误结论。

### 3.2 参考实现参数

| 参数 | 取值 | 理由 |
|---|---|---|
| 阵列规模 | 128×128 MAC | 与 OzCore 基线一致，便于对齐 |
| 收缩维 K | 128 | 与 OzCore 基线一致 |
| 工艺 | 28 nm CMOS | 与 OzCore 一致；另做先进节点投影 |
| 频率 | 300 MHz | 与 OzCore 一致；另做 f_max 扫描 |
| 累加器 | INT32 / FP32 | 三种格式的典型配置 |
| 流水 | 与各格式的自然流水一致，但要求吞吐匹配 | 不强行统一级数，避免人为拉平 |
| 面积边界 | 阵列 + 前后处理 + 控制 | 不含 SRAM/NoC |
| 能耗边界 | 动态 + 漏电，300 MHz | 与论文的 PrimePower 口径对齐 |

### 3.3 三种格式的分解逻辑（比较对象）

- **INT8（OzCore）**：缩放 → 模数分解（模数接近 2⁸）→ `s` 次 INT8 GEMM（INT32 累加）→ 模约简 → CRT 重构 → 反缩放。`s` 控制精度/吞吐。
- **FP8 E4M3（Uchino et al.）**：缩放 → 模数分解 → 每个模数用 3 次 FP8 GEMM（把剩余拆成高位/低位部分积，FP32 累加）→ 模约简 → CRT → 反缩放。模数 p≤513；达到 FP64 精度需要 N≥13 个模数。
- **FP4 E2M1（Hayashi et al.）**：缩放 → base-13 limb 分解（p×q 个 limb 平面）→ FP4 GEMM（FP32 累加）→ limb 重构 → 反缩放。DGEMM 下 OzII-FP4 约需 19 个模数，OzI-FP4 约 p=q=15 个 limb。

三种方案的 pass/limb 数不同，因此“有效吞吐”必须按目标精度分别计算，不能直接用峰值 TOPS 比较。

### 3.4 公平比较规则

| 维度 | 规则 |
|---|---|
| 阵列规模/收缩维 | 统一 128×128、K=128 |
| 工艺/频率 | 统一 28 nm、300 MHz；另做缩放/频率敏感性 |
| 累加器 | INT32（INT8）/ FP32（FP8、FP4） |
| 辅助逻辑 | 三种格式各自的预处理/后处理都计入；不允许只报 MAC 阵列 |
| 精度目标 | 同一目标下比较（BF16 等价 / FP32 等价），不允许用不同精度“各取最优” |
| pass 数 | 用同一精度目标下的最小 pass/limb 数；由实验测定 |
| 综合/功耗 | 同一综合工具、同一单元库、同一工艺角、同一活动率方法 |
| 数据/工作负载 | 同一组 GEMM 形状、同一组 LLM 层、同一输入动态范围 |
| 报告粒度 | 峰值（per-MAC）与等精度有效值分开报告 |

## 4. 评价指标

### 4.1 原始硬件指标

对每种格式的单格式执行部件：

- `A_total`：总面积（mm²）= 阵列 + 预处理 + 后处理 + 控制；
- `P_total`：总功耗（W）= 动态 + 漏电，300 MHz；
- `T_peak`：峰值吞吐（TOPS）= 2 × MAC 数 × 频率（1 MAC = 2 次运算，报告时注明口径）；
- `E_mac`：单 MAC 能耗（pJ），可由 `P_total` 与活动率反推，作为辅助指标。

### 4.2 等精度有效指标

设达到目标精度需要 `Q` 次低精度 GEMM（INT8 的 `s`、FP8 的模数×3、FP4 的 limb/模数组合），则：

```
T_eff = T_peak / Q                    [TOPS]
```

把预处理/后处理的开销计入 `A_total`、`P_total`（它们已经包含在整机中），得到：

- **有效面积效率**：`EAE = T_eff / A_total` [TOPS/mm²]
- **有效能耗效率**：`EEE = T_eff / P_total` [TOPS/W]
- **面积–能耗效率**：`AEE = T_eff / (A_total × P_total)` [TOPS/(mm²·W)]
- 等价地，**面积–能耗积**：`AEP = 1 / AEE` [mm²·W/TOPS]，越小越好

`AEE` 同时惩罚“面积大”和“功耗高”，是本方案的主指标；`EAE`、`EEE` 分开报告，便于解释是面积占优还是能耗占优。

### 4.3 精度指标

- **相对 L2 误差**：`||C_ref − C||_F / ||C_ref||_F`，参考值为 FP64/FP32 精确结果；用于随机矩阵和真实 GEMM。
- **LLM 困惑度（PPL）**：LLaMA-3.1 8B 在 WikiText-2 上相对 BF16 的 PPL 差；BF16 等价目标定义为 PPL 差在预设阈值内（暂定 ≤ 0.5%，需确认）。
- **零样本准确率**：HellaSwag/ARC/WinoGrande/MMLU 等，作为 PPL 的补充。
- **有效精度**：由相对 L2 误差或 SQNR 换算的有效位数，用于解释 pass 数。

### 4.4 判定规则（预注册）

1. 在 **BF16 等价**目标下，按 `AEE` 排序；若第一名领先第二名超过测量不确定度（暂定 > 2σ 且 > 15%），记为显著领先。
2. 在 **FP32 等价**目标下重复上述排序。
3. 若两个目标的赢家不同，输出 Pareto 前沿，并按“目标工作负载 + 扩展成本”给出推荐；不强行选一个“全能冠军”。
4. 若三者差异都小于不确定度，结论为“在现有方法下无显著差异”，需要更高保真流程再判。
5. 任何格式若无法在合理 pass 数内达到目标精度（例如 FP4 的 limb 数爆炸），直接排除并说明原因。

## 5. 面积与能耗估算方法

### 5.1 流程总览

```
格式规范 + 分解算法（Python 位精确模型）
        │
        ▼
参数化 RTL / HLS（阵列 + 预处理 + 后处理）
        │
        ├── 逻辑综合（28 nm）→ 面积、时序、门级网表
        ├── 功耗分析（PrimePower 或 OpenSTA + VCD/SAIF）→ 动态/漏电
        ├── 精度/pass 数（软件模型 + LLM/GEMM 实验）
        │
        ▼
等精度有效吞吐 → TOPS/mm²、TOPS/W、AEE → 排名/Pareto
```

### 5.2 面积与时序

- **主流程（对齐论文）**：Siemens Catapult HLS + 28 nm 标准单元库 + Design Compiler；300 MHz 下满足时序，报告总面积和分块面积（阵列 / 预处理 / 后处理 / 控制）。
- **开源备选（可复现）**：SystemVerilog + Yosys + Sky130 HD + OpenSTA；同一 RTL、同一约束，报告 µm²/kGE 和关键路径。两套流程的绝对面积会不同，但相对排名应一致；若不一致，以商用流程为主、开源流程为交叉校验。
- **分块面积**：必须拆分到 MAC 阵列、预处理、后处理、控制四块；这是解释“为什么某个格式赢”的关键。
- **工艺缩放**：主结果 28 nm；用公开的 7 nm/5 nm 缩放因子给出投影，并标注为估算。

### 5.3 能耗

- **主流程**：综合后网表 + 真实活动率（VCD/SAIF）→ PrimePower；报告动态、漏电、时钟网络、各分块功耗。
- **开源备选**：OpenSTA `report_power` + VCD；若流程不可用，用 Liberty 引脚电容 + 内部功耗表 + 翻转计数的 Python 估算器，并用 Horowitz 45 nm 模型交叉校验。
- **活动率**：随机均匀/正态操作数 + 真实 LLM 激活/权重 trace；至少 5 组种子，报均值 ± 95% CI。
- **能耗口径**：单次目标 GEMM 的总能耗（阵列 + 前后处理）除以有效运算数；同时报告每次低精度 MAC 的能耗，便于解释。
- **漏电**：在 300 MHz、TT 25 °C 下报告；FF/SS 作为敏感性。

### 5.4 pass 数与精度

- **位精确模型**：用 Python/NumPy 实现三种格式的编码、缩放、分解、累加、重构；与 RTL 用随机向量对拍（≥10⁶ 条），确保语义一致。
- **pass 数扫描**：对每种格式扫描 `s`/模数/limb 数（例如 INT8 s=2..12；FP8 模数 2..13；FP4 limb 2..19），记录相对 L2 误差和 PPL。
- **最小 pass 数**：在 BF16 等价和 FP32 等价两个目标下，取满足精度的最小配置；这是 `Q` 的来源。
- **工作负载**：LLaMA-3.1 8B（PPL + 零样本）、随机 GEMM（不同动态范围 φ）、真实 LLM 层 GEMM；HPC 场景加 DGEMM 形状。

### 5.5 交叉校验

- **对齐 OzCore 公开数字**：用 INT8 基座复现 6.03 mm²、27.9% 前后处理开销、21.0 TOPS/W（INT8 峰值）、s=3 的 BF16 等价 PPL；若偏差 > 20%，先修流程再比较。
- **对齐 FP8/FP4 论文的 pass 数趋势**：FP8 DGEMM 约 13 模数、FP4-OzII 约 19 模数；用于验证模型。
- **面积/功耗**：与已发表的同类阵列数据按工艺缩放对比，偏差 > 2× 时检查流程。
- **精度**：软件模型 vs RTL 逐位一致；LLM 结果 vs 公开实现一致。

### 5.6 统计与敏感性

- 综合/功耗：3 次独立综合（不同 seed/约束微扰）报均值与范围；
- 工艺角：TT/FF/SS；
- 频率：300 MHz + 各格式 f_max；
- 阵列规模：64×64、128×128、256×256；
- **FP4:FP8 吞吐比**：1.5×、2×、3×、4×（这是 FP4 能否胜出的关键参数）；
- 精度目标：BF16 等价、FP32 等价（可选 FP64 等价）；
- 工艺节点：28 nm 主结果 + 7/5 nm 投影；
- 累加器宽度：主配置 + 窄累加器敏感性。

### 5.7 可复现性

- 固定工具版本、PDK 版本、综合脚本、功耗脚本；
- 一键复现：`make synth`、`make power`、`make accuracy`、`make report`；
- 原始数据（CSV/JSON）、网表、VCD 抽样、图表脚本全部入库；
- 报告中的每个数字都能追溯到某次 run 的产物；
- 论文 PDF 不进入仓库（版权），只在报告中引用。

### 6.4 里程碑与 go/no-go

- **M1（P0）**：INT8 基座复现误差 < 20%；否则先修流程，不进入 P1。

- **M3（P3）**：两个精度目标下都有至少两种格式达到目标；否则调整 pass 扫描范围或精度目标。
- **M4（P4）**：结论通过工艺、规模、吞吐比、累加器敏感性检查后，才作为选型建议。

## 7. 预期结果与假设（待验证，不是结论）

- **H1（原始效率）**：按峰值 TOPS/mm²、TOPS/W 排序，预计 FP4 > FP8 ≈ INT8；FP4 的乘法器和操作数位宽最小，但前后处理（base-13 编解码）会抵消一部分优势。
- **H2（BF16 等价）**：INT8 需要约 3 个 pass，FP8/FP4 需要更多；若 FP4 的 2× 吞吐能覆盖其增加的 limb 数，FP4 可能在等精度 AEE 上胜出；否则 INT8 或 FP8 领先。关键比值是“FP4:FP8 吞吐比 / pass 数比”。
- **H3（FP32/FP64 等价）**：需要更多 pass，FP4 的 limb 数增长最快（论文的 DGEMM/FP64 配置下约 19 模数 vs FP8 13 模数）；FP4 的优势可能缩小甚至消失，INT8/FP8 更稳。
- **H4（无全能赢家）**：很可能没有一种格式在两个精度目标、所有工作负载上都最优；最终报告应给 Pareto 前沿和“按目标推荐”的规则。
- **H5（扩展成本）**：从基座格式扩展到完整 I/O 格式集（FP32/FP16/BF16/FP8/INT8）的增量面积，INT8 与 FP8 可能接近，FP4 因编解码逻辑而更高；这会成为平局时的判据。

这些假设如果被数据推翻，报告要如实写出，并解释原因（例如前后处理主导、pass 数爆炸、累加器瓶颈）。

## 8. 风险与备选方案

| 风险 | 影响 | 缓解/备选 |
|---|---|---|
| FP8/FP4 分解算法实现复杂 | pass 数/精度曲线不可信 | 先用论文的位精确模型复现；与论文报告的趋势对齐后再上硬件 |
| FP4 在开源 EDA 中无原生支持 | 面积/功耗估算偏差 | 用 E2M1 的定点/整数等价实现；商用 HLS 做交叉校验；明确建模假设 |
| 28 nm 结果不能代表先进节点 | 结论可能随工艺变化 | 主结果 + 7/5 nm 投影；把工艺敏感性作为结论的一部分 |
| 前后处理面积/功耗建模不准 | 排名被辅助逻辑左右 | 与 OzCore 的 27.9% 开销对齐；分块报告；敏感性分析 |
| 精度目标定义主观 | 赢家随阈值变化 | 预注册 BF16/FP32 等价阈值；同时给 Pareto 曲线，不只报单点 |
| FP4:FP8 吞吐比是假设 | FP4 结论依赖该假设 | 扫描 1.5–4×；给出 break-even 比值，而不是只报一个点 |
| LLM 实验成本高 | 进度拖延 | 先用随机 GEMM + 小模型校准；LLaMA-3.1 8B 只做最终确认 |
| 论文最优实现不等于公平实现 | 比较对象错位 | 三种格式在同一流程下重实现；论文数据只作校验 |
| 只比较 MAC 阵列 | 结论误导 | 强制包含预处理/后处理；面积/能耗分块报告 |

## 9. 待确认问题

以下问题不影响方案成立，但会影响最终推荐，建议在 P0 结束前确认：

1. 主目标场景是 LLM 推理（BF16 等价）还是 HPC 高精度（FP32/FP64 等价），或两者都要？
2. 目标工艺节点：28 nm 演示，还是 7/5 nm 决策？
3. “执行部件”的边界：仅 128×128 阵列 + 前后处理，还是包含 SRAM/寄存器堆的 tile？
4. BF16 等价的可接受 PPL 差（暂定 ≤ 0.5%）和 FP32 等价的相对 L2 误差阈值。
5. 是否有商用 EDA（Catapult/DC/PrimePower）可用；若没有，是否接受开源流程的相对排名？
6. 是否把 INT4 权重/MXFP4 纳入后续扩展（可能改变基座选择）。

## 附录 A：三种格式的数值要点

| 格式 | 符号 | 指数 | 尾数（显式） | 偏置 | 最大有限值 | 最小正值 | 备注 |
|---|---|---|---|---|---|---|---|
| INT8 | 1（补码） | — | 7 数值位 | — | 127 | 1 | 精确整数 |
| FP8 E4M3 | 1 | 4 | 3 | 7 | ±448 | 2⁻⁶ | 无 Inf，NaN 特殊编码 |
| FP4 E2M1 | 1 | 2 | 1 | 1 | 6 | 0.5 | 值集 {0,±0.5,±1,±1.5,±2,±3,±4,±6} |

FP4 的关键性质：所有 FP4 值乘 2 后都是整数；base-13 表示用 `log2(13) ≈ 3.70 bit/limb`，比按位截断更省 limb。
