# Ozaki I 与 Ozaki II：理论计算过程、矩阵乘/时间开销分析

> 依据：Ozaki, Uchino, Imamura, *Ozaki Scheme II: A GEMM-oriented emulation of floating-point matrix multiplication using an integer modular technique*（2026）；OzCore（MICRO 2026）§II；FP8/FP4 变体论文。
> 代码：`experiments/ozaki1-vs-ozaki2/model/ozaki_cost.py`、`plot_cost.py`；结果：`experiments/ozaki1-vs-ozaki2/results/`。

## 1. 结论摘要

1. **Ozaki II 并非在所有精度/形状下都优于 Ozaki I**。在 BF16（B=8）等低精度、K=1024–16384 的范围内，I 的快速模式只需 3 次 GEMM（k=2），少于 II 的 4 个模数；II 的 CRT 重构又更重，因此 I 更快。
2. 随目标精度提高，II 的线性 GEMM 次数优势压过 CRT 开销：FP64（B=53）下 I 需 36 次 GEMM，II 只需 15 次；II 的总时间约为 I 的 0.44–0.69×。
3. FP16/FP32 存在交叉点：K=1024 时 I 更快或接近（FP16 II/I=1.05，FP32=1.28），K≥4096 时 II 反超（FP16 0.80，FP32 0.97）；K=16384 时 II 明显更快（0.71/0.85）。
4. 小矩阵的非 GEMM 开销确实很高：K=1024 时 GEMM 只占 38–63%，变换/重构/存储合计 37–43%；K=4096 时降到 13–29%；K=16384 时 3–9%。这与文献中 27–55% 的“困难区间”一致。
5. 对 OGE 的启示：**默认 Ozaki II，但保留 Ozaki I 作为 BF16/小 K 回退**；精度合同应按 B、K、动态范围在两者间选择，而不是固定一个算法。

## 2. Ozaki I 的理论计算过程

### 2.1 分解与缩放

把 A、B 拆成 k 个低精度切片，并用 2 的幂对角矩阵 D_i、E_j 做无误差缩放：

```
A ≈ Σ_{i=1..k} D_i^{-1} (D_i A_i)
B ≈ Σ_{j=1..k} (B_j E_j) E_j^{-1}
```

D_i A_i 与 B_j E_j 的元素可用低精度格式精确表示；乘积与 q 项累加在目标累加器（FP32 或 INT32）中无舍入。INT8 基下，若 q<2^17，7-bit 有效尾数可保证乘积精确；FP16 基下切片精度由 `floor((24-log2 q)/2)` 位决定。

### 2.2 矩阵乘：fast 与 accurate

- **fast**：只算 i+j≤k+1 的切片对，
  `C ≈ Σ_{i+j≤k+1} D_i^{-1}[(D_i A_i)(B_j E_j)]E_j^{-1}`，
  GEMM 次数 `Q_I = k(k+1)/2`。
- **accurate**：算全部 k² 对，`Q_I = k²`。

论文 Table 2 给出 fast 模式：k=2..10 → Q_I=3,6,10,15,21,28,36,45,55；本报告程序复核完全一致。

### 2.3 代价

| 部分 | 内容 | 复杂度 |
|---|---|---|
| Part 1 | 切片 + 缩放 | O(k(pq+qr)) |
| Part 2 | Q_I 次低精度 GEMM | Q_I·pqr |
| Part 3 | FP64 加权归约/缩放 | O(Q_I·pr) |

当 p=q=r=K 足够大时，Part 2 主导；但 K 较小时 Part 3 与切片存储不可忽略。切片数近似 `k≈ceil((B+g_s)/b_s)`，INT8 基 b_s=8、g_s≈6；本报告取 k=2/3/4/8 对应 BF16/FP16/FP32/FP64。

## 3. Ozaki II 的理论计算过程

### 3.1 缩放、取模与 CRT

1. 缩放/截断：`A′=trunc(D·A)`，`B′=trunc(B·E)`，D、E 为 2 的幂。
2. 选 s 个两两互素模数 m_1..m_s，`M=∏m_i`；对称余数：
   `A′_i=A′ mod m_i`，`B′_i=B′ mod m_i`。
3. 每个模数一次低精度 GEMM：`C_i=A′_i B′_i`。
4. CRT 重构：`C′ ≡ Σ_i C_i·M_i·y_i (mod M)`，其中 `M_i=M/m_i`，`y_i=M_i^{-1} mod m_i`。
5. 反缩放：`C≈D^{-1}C′E^{-1}`。

### 3.2 精确性条件

CRT 唯一性要求整数乘积落在 `(-M/2, M/2)`：

```
2·max|A′B′| < M
```

若 `max|A′||B′|` 的上界为 `q·2^{kA+kB}`，则

```
kA + kB = floor(log2((M/2 - 1)/q))
```

INT8 基下模数取 2..256 的两两互素数（256,255,253,...）；q<2^17 时 INT32 累加精确。FP64 目标通常需要 s=15–16 个模数（论文示例 s=16、M≈2^125）；本报告取 s=4/4/8/15 对应 BF16/FP16/FP32/FP64。

### 3.3 代价

| 部分 | 内容 | 复杂度 |
|---|---|---|
| Part 1 | 缩放/截断 | O(pq+qr) |
| Part 2-a | s 次取模 | O(s(pq+qr)) |
| Part 2-b | s 次低精度 GEMM | s·pqr |
| Part 2-c | 加权累加 | O(s·pr) 宽整数 |
| Part 3 | mod M / 唯一候选 | O(pr) 宽整数 |
| Part 4 | 反缩放 | O(pr) |

Q_II=s；CRT 后端的宽整数乘加比 I 的 FP64 归约更重，这是 II 在低精度/小 K 下可能输给 I 的原因。

## 4. 统一代价模型

设 p=q=r=K，目标精度 B（BF16=8、FP16=11、FP32=24、FP64=53），单模数/切片位宽 8 bit：

```
k = ceil((B + 6)/8)          Q_I  = k(k+1)/2
s = ceil((2B + 10)/8)        Q_II = s
```

时间（cycles，串行相加，保守）：

```
T_I  = 2kK²/R_e + Q_I·K³/R_mac + 2Q_I·K²/R_e + B_I/BW
T_II = 2sK²/R_e + Q_II·K³/R_mac + s·K²/R_c + K²/R_e + B_II/BW
B_I  = (2k + 4Q_I)K²      B_II = (2s + 4s)K²
```

参数：`R_mac=16384`（128×128 INT8、1 MAC/cycle）、`R_e=128` 元素操作/cycle、`R_c=16` CRT 宽操作/cycle、`BW=256 B/cycle`、1 GHz。存储按 INT8 切片/余数 1 B、部分积 4 B 计；未建模重叠，因此非 GEMM 占比偏保守。

## 6. 讨论

### 6.1 为什么 II 不是总优

- Q_I 随 k 平方增长，Q_II 随 s 线性增长；**高精度**（FP64）II 的 GEMM 次数优势压倒 CRT。
- **低精度**（BF16）时 I 只需 k=2（Q_I=3），II 为覆盖 2B 范围至少需要 4 个模数（Q_II=4）；I 的 GEMM 更少、后端更简单，因此 I 更快。
- **小 K** 时 CRT 后端的 O(s·pr) 宽整数操作无法被 GEMM 摊薄；II 的 post 占比 38–39%，I 只有 14–15%，因此 I 在 BF16/FP16/FP32 的小 K 下可能反超。
- 交叉点：BF16 下 I 始终更快（本模型 K≤16384）；FP16/FP32 在 K≈2–4K 附近交叉；FP64 II 始终更快。

### 6.2 矩阵乘开销

- GEMM 次数比 Q_I/Q_II：BF16 0.75、FP16 1.5、FP32 1.25、FP64 2.4。
- 但时间比不等于次数比：II 的 CRT post 更重，I 的切片存储/归约更重；只有 GEMM 占主导（K≥4096/16384）时，次数比才接近时间比。
- 对 FP64：II 用 15 次 GEMM 换 36 次，GEMM 时间 0.42×；加 CRT 后总时间 0.44–0.69×。
- 对 BF16：I 用 3 次 GEMM 换 4 次，GEMM 时间 0.75×；加后端后 I 仍 1.41–2.02× 更快。

### 6.3 对 OGE 的启示

- **默认 Ozaki II**：FP32/FP64 中大规模 GEMM 上 II 的线性 GEMM 次数优势明确。
- **保留 Ozaki I 回退**：BF16、K≤1024–4096、或 CRT 后端面积受限时，I 可能更优；精度合同可按 B、K、动态范围选择。
- **小矩阵优化重点**：K=1024 时非 GEMM 37–43%，其中 CRT post 是 II 的主要负担；FTU/CRT epilogue/双缓冲正是把这一部分压到 <10% 的关键。
- **不要把“II 一定优于 I”写进前提**：开题报告已把算法族选择降为 WP1 的次要规则，本分析给出定量依据。

## 7. 模数 s 的划分与选择细节

### 7.1 s 控制什么

Ozaki II 选 s 个两两互素的模数 \(m_1,\dots,m_s\)，令

```
M = ∏_{i=1..s} m_i,   M_i = M/m_i,   y_i = M_i^{-1} mod m_i
```

每个模数对应一个残差平面、一次低精度 GEMM、一个 CRT 加权项：

```
C′ ≡ Σ_i C_i · M_i · y_i (mod M)
```

s 同时决定三件事：

1. **可恢复的整数范围**：CRT 唯一性要求 `M/2 > max|A′B′|`；
2. **GEMM 次数**：Q_II=s；
3. **后端开销**：s 次取模、s 次加权、128-bit 累加与 mod M。

### 7.2 精确性下界与 s_min

设目标有效位 B、内维 q=K、缩放/舍入 guard g，则整数乘积上界约为 `q·2^B`，需要

```
M/2 > q · 2^B     ⇒     log2(M) > B + log2(q) + 1
```

再加 guard g（动态范围/截断），得到

```
s_min = min{ s : Σ_{i≤s} log2(m_i) ≥ B + log2(K) + g }
```

以 K=4096（log2K=12）、g=2 为例：

| 目标 | B | B+log2K+g | s_min | s_min 的 M bits |
|---|---:|---:|---:|---:|
| BF16 | 8 | 22 | 3 | 23.98 |
| FP16 | 11 | 25 | 4 | 31.95 |
| FP32 | 24 | 38 | 5 | 39.90 |
| FP64 | 53 | 67 | 9 | 71.33 |

注意这是**精确性下界**，不是实际选型：截断误差、舍入、极端动态范围、以及“CRT 恢复后还要正确舍入到 B 位”都需要额外余量。实际工作常用更保守的 s：OzCore 在 BF16 用 s=3；论文 FP64 用 s=16；本报告代价模型用 4/4/8/15（BF16/FP16/FP32/FP64）。

### 7.3 模数如何选：贪心降序 + 两两互素

INT8 基下模数取 `2 ≤ m_i ≤ 256`，这样对称余数落在 `[-128,127]`，可放进有符号 INT8。为了在固定 s 下最大化 M，按降序贪心取两两互素的数：

```
256, 255, 253, 251, 247, 239, 233, 229,
227, 223, 217, 211, 199, 197, 193, 191, ...
```

- **256 是唯一的偶数模数**：`256=2^8`，与所有奇数互素；对称取模得到 `[-128,127]`，`128` 按补码映射到 `-128`，`128 ≡ -128 (mod 256)`，不影响同余类。
- 其余取奇数且两两互素；255=3·5·17 不是素数，但与 256、253、251 等互素，可使用。程序已对 16 个模数两两 `gcd` 校验。
- 为什么不取 1：模数 1 不提供信息；为什么不取合数偶数：会与 256 不互素，破坏 CRT。
- 对 FP8 基，模数 p≤513（9 bit），每个模数 3 次 FP8 GEMM；对 FP4 base-13 基，模数/limb 结构不同（19 模数/75 GEMM）。本节以 INT8 为例。

s 与 M 的对应（K=4096 的 `kA+kB` 由 Eq. 16 计算）：

| s | m_s | M bits | kA+kB (q=4096) |
|---:|---:|---:|---:|
| 3 | 253 | 23.98 | 10 |
| 4 | 251 | 31.95 | 18 |
| 5 | 247 | 39.90 | 26 |
| 8 | 229 | 63.50 | 50 |
| 9 | 227 | 71.33 | 58 |
| 15 | 193 | 117.46 | 104 |
| 16 | 191 | 125.04 | 112 |

`kA+kB` 是缩放后可用的输入位宽上界；FP64 目标只需 53 位，所以 s=9 已满足“范围”要求，s=15/16 提供的是**精度余量**（截断/舍入/动态范围），不是 CRT 唯一性的硬性要求。

### 7.4 一个 FP64 例子

- B=53、K=4096、g=2：`s_min=9`（M bits 71.33 > 67），理论上可恢复 53 位整数乘积。
- 但输入缩放后的截断、CRT 加权前的 mod、最终舍入都会损失有效位；为把误差压到 FP64 级，需要更多模数。论文用 s=16（M bits 125.04，kA+kB≈112）；本报告代价模型用 s=15（M bits 117.46，kA+kB≈104）。
- 代价：s=15 的 Q_II=15 次 GEMM，s=9 只需 9 次；多出的 6 次 GEMM + 6 个 CRT 项换精度余量。这个 trade-off 正是“精度合同”要暴露给应用的参数：`BOUNDED(ε)` 可选 s=9–12，`EXACT` 选 s=15–16。

### 7.5 s 在硬件上的划分/调度

- **slot 划分**：每个模数一个 CRT slot；s 个 slot 加权累加。OzCore 有 12 个 slot，支持 s∈{2,3,4,6,12}（s 整除 12，slot 分组）；s=15/16 超过 12，需要：
  - 16 个 slot 的 OGE 变体；或
  - 时间复用：12+3/4 两批，两批都按完整的 `M_i y_i` 权值累加（CRT 是线性的，分批累加不改变最终和），代价是后端多一遍；或
  - 子阵列并行：每个子阵列负责一部分模数，最后 128-bit 累加。
- **GEMM 划分**：s 个模数独立；默认模数串行复用同一 INT8 阵列（面积小），对延迟敏感可把 s 分到多个子阵列并行（面积换吞吐）。
- **流水**：第 i 个模数的 GEMM 与第 i+1 个模数的取模/残差平面生成重叠；CRT 的加权可与下一个 tile 的 GEMM 重叠；s 越大，流水越能隐藏后端，但 slot/带宽压力越大。
- **s 的自适应**：运行时按精度合同、动态范围、K 选择 s；若 `M/2` 不够，增大 s；若 s 超过硬件 slot，分批或回退；若 K≥2^17，INT32 累加可能溢出，需按 K-block 分块或加宽累加器。

### 7.6 选择伪代码

```python
MODULI = [256,255,253,251,247,239,233,229,227,223,217,211,199,197,193,191]

def choose_s(B, K, guard=2, s_max=16):
    need = B + math.ceil(math.log2(K)) + guard
    P = 1
    for s, m in enumerate(MODULI[:s_max], 1):
        P *= m
        if math.log2(P) >= need:
            return s
    return s_max

# 精确性下界；实际选型再加 accuracy_guard 个模数
s_exact = choose_s(53, 4096, guard=2)      # 9
s_practical = choose_s(53, 4096, guard=8)  # 10；论文/本报告用 15/16 还包含额外误差/舍入余量
```

## 8. 限制

- 这是**串行相加的解析代价模型**，未建模 FTU/GEMM/CRT 的重叠、流水填充、SRAM bank 冲突、实际 GPU/ASIC 的利用率；绝对值只用于相对比较。
- Q_I/Q_II 的 k/s 由经验 guard 校准（I 与论文 Table 2 对齐；II 比论文示例少 1 个模数），不同输入分布/缩放会改变实际所需次数。
- 本分析未做数值误差仿真；误差/通过次数的数值验证见 `experiments/ozaki-format-comparison/` 的 FP8/FP4/INT8 模型，以及后续 WP1 的 Ozaki I/II 误差实验。
- 参数 `R_e=128`、`R_c=16`、`BW=256` 是设计假设；改变这些参数会移动交叉点，需在 RTL/模拟器中标定。
